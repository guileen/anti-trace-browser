# Change: 三路运行时赛马、严格验收与双轻内核实现

## Why

产品目标：反追踪、抗审查的多环境管理及 AI headless 自动化，保留基本 GUI 操作、人机接管和二次开发能力。用户优先考虑轻量、性能与定制成本；复杂历史兼容性降权。环境由 seed、自定义覆盖、代理和隔离存储组成，通过自解释 CLI 使用。

现有 Camoufox 作为功能与策略基准；Obscura、Lightpanda 按相同工程切片比较。此前客户端连接结果、UA校验或语言曾影响路线判断；实施前判分器又把普通跳转判为cleared、空观察判为reached。本轮已修判据并完成双候选源码实验；JS层具体语义风险与构建、GUI、持久存储成本分别记账。

## What Changes

- 先校准检查项：独立记录配置稳定、跨环境差异、功能语义、跨站关联、网络路径、挑战回执和性能；每项带版本、输入、原始证据及覆盖状态。
- Obscura/Rust 与 Lightpanda/Zig 两路都实现配置、存储、真实页面画面与输入、协议、安全与维护能力；Camoufox同场按统一清单复验。实施前不选赢家，最终路线待完整证据再比较。
- 持久 EnvironmentSpec 在网页执行前进入运行时；seed 与显式覆盖派生出版本化 resolved 配置，页面/iframe/Worker/网络共享同一契约。复用 Camoufox 策略并逐文件审查许可证。
- 2026-11-04目标修订：轻内核以真实Canvas/Audio/WebGL计算、环境内稳定和环境间可解释差异为核心，Chrome作为兼容与统计参考。像素/样本统计与输入响应、真实功能、数据来源交叉验收，精确复刻Chrome输出退出交付门槛。
- 保留 CLI，run 升级为熟悉的 Python Playwright 异步脚本入口，单次会话内完成循环、分支、等待和结果提取；axtree 引用绑定页面与观察版本，人工接管具有独占写权限。
- 自有 fingerprint-test.ipub.io 用 Turnstile 服务端回执提供挑战证据；SEO 说明页、合成门禁和真实挑战分别标识。账号凭据与生产 WAF 规则保持独立。
- Camoufox 转入基准维护，固定每轮实验版本；安全更新、回归和已确认缺陷继续维护。
- 新增独立 `core/mioa-headless/` headless 服务；页面、网络、存储与像素保持单一所有者，供本机 CLI 与自动化客户端复用。

## Scope

本 change 覆盖判据修正、双候选完整实现、三路统一CLI接入、基本 GUI、人机共享会话、脚本自动化和自有靶场验收。两路实现不依赖先选主线；最终选型是验收后的决策，不阻断开发。

首轮平台为macOS arm64。当前定制headless的真实GL后端依赖macOS CGL，平台状态按实际构建与运行证据登记。MCP、完整历史浏览器兼容、Chromium/Gecko全量自编译、生产账号试错和通用商业风控通行承诺均在本change范围之外。Moli/Fury保留历史或外部对照入口。

## 本次提案：真实指纹与稳定环境

状态：提案与验收设计已修订；新增判据及运行时改造待实施。当前headless与三路历史验收保持原状。

### 决策与目标

核心价值是可信、可定制的轻量浏览器运行时。计算语言和单个hash作为诊断，实际输入经过真实图形/音频管线产生什么结果，承担功能验收。

| 目标 | 交付依据 |
|---|---|
| 真实能力 | 文字/路径/图像由真实排版与绘图产生；Audio执行实际节点图；GL编译和执行shader并读回结果 |
| 统计行为合理 | 颜色、透明度、边缘与空间结构，音频能量/频谱等符合给定输入与功能；参考浏览器样本提供经验对照 |
| 同环境稳定 | 固定配置/资产/backend/版本，重复、刷新、新页、重启及支持realm稳定，迁移显式产生新revision |
| 不同环境可区分 | 通过真实字体、渲染/计算配置等受支持组合产生可复现差异，成因、输出及功能代价一同保存 |

“服务端可能使用像素统计”作为待验证威胁模型；独立检验同时覆盖hash、内容、统计和输入响应。少量本机样本提供工程对照，全球分布与真实站点判定按采集覆盖单列。

### 实现边界

- 复用已有真实渲染/DSP/GL能力，先审查软件声明与真实功能的一致性；Chrome与Camoufox提供参考样本。
- seed选择受支持配置并持久化实际结果；网页只获得正常Web API，内部seed与管理器能力留在宿主。
- 每路仅一个DOM、网络和存储所有者。共享viewer只显示真实headless像素并转发受租约保护的输入。
- 环境组合需要整体自洽；某些真实物理输出可共享，A/B可区分以预先声明的真实差异组合验收。
- 精确复制某版Chrome的全部像素、编码和浮点结果、为已知探针专门返回答案、生产账号试错及商业风控通行保证列为非目标。

### 四阶段交付

1. **审判器校准**：建立独立输入、原始数据、统计口径及负例；先证明能接受真实简单输出，并识别固定输出、错误空间内容和忽略输入的计算。
2. **能力与声明自洽**：修复真实功能/对象/异常/跨realm缺口；统一HTTP、JS声明与实际支持。每条路线独立留证。
3. **环境稳定与真实差异**：固定资源和计算路径，完成A1/B1/A2/B2及刷新/新页/Worker/iframe矩阵；逐项解释差异来源。
4. **完整任务与性能**：在同能力、同任务和同资源条件下比较三路；功能、真实性、稳定、差异、网络、第三方挑战和性能分别报告。

### 检查点与停止条件

- 检查输入、阈值来源、负例和成本上限在对应实现实验前固定，阈值变化产生新规则版本。
- 单一hash或直方图相近属于局部观察，完整放行要求语义、数据来源、生命周期、隔离和任务证据共同成立。
- 某项改动若破坏真实功能、读回/显示一致性、环境稳定或资源预算，则回退该改动并提交成因与成本；优先保留可用真实能力。
- 差异方案若只能增加不自洽的声明或输出，保留已测共有值并记录差异门槛缺口；后续依据真实backend/字体/DSP实验继续选择。
- 本次审核聚焦可维护的真实管线；比较结果决定后续投资，Lightpanda/Obscura两路继续，Camoufox作为可用基准。

详细I/O、统计口径与Mind-Test见[design](design.md)，可观察验收见[spec F1–F3](specs/lightweight-runtime/spec.md)，实施见[tasks §7](tasks.md#7-真实指纹统计语义与稳定环境2026-11-04用户修订)。

## Impact

- `cli/`：环境契约、运行时适配、run/axtree、租约、audit/field。
- `services/audit/`：版本化验收清单、独立输入探针与证据状态。

- `browsers/obscura-runtime/`、`lightpanda-runtime/`：分别交付两条可重放原生实现；从产品路径移除旧注入和模拟实现，历史原始报告保留。共享管理与测试契约，不共享独立环境的可变状态。
